Router_ {

This and my switch is what I really wanted to learn how to setup myself. I bought a Topton mini pc with a Celeron CPU and 8gb DDR4 + 128gb m.2 nvme ssd. This device came with PfSenseOS already flashed onto the device. I was able to access the admin panel via LAN and can also utilize via shell.

PfSenseOS is a FreeBSD derivative and works slightly different than the typical Linux and BSD systems. The traditional way to handle the networking stack software config was by having each service split up on their own '.conf' files. PfSenseOS instead centralizes this whole whole config onto one XML document. This is why they recommend just utilizing the webGUI for PfSenseOS admin panel. There are some tasks that are safe for the shell to perform.

    _PfSenseOS - Shell safe tasks {

  • Running diagnostic utilities : ifconfig, netstat, pfctl -sr, top, ping, traceroute.
  • Reading system logs : clog, dmesg.
  • Running automated scripts that inspect network state.

    • }

I currently utilize minimal services on my PfSenseOS Router. I utilize Unbound (default DNS resolver), pfBlocker-NG, Wire Guard VPN Tunnel and Suricata. I also utilize Tail scale and have my whole LAN setup with the Tail scale network. This setup is nice because, if I am away from home and need to access something that I don't have on my laptop. I will end up just using SSH and the 'scp' command to perform a file transfer via SSH port. I can also just access whatever drives that I place into my Samba configuration file and share to my LAN and then pull them directly. If I remember correctly, Samba utilizes port 445 and will fall back to 443 if anything prevents the 445 access.

I wanted to set up my own Routing and Firewall etc. Admittedly, I didn't have to perform the tough part in setting up my PfSenseOS and mini PC. It was pre-flashed and already had the software on it. I had to set all the rules via webGUI. I wanted to attempt a headless install of PfSenseOS and enable Packet Filter(Firewall/NAT engine), ipfw(Firewall). I have never set up a Linux OS with iptables or iptables-nft | nft , whichever user space name it is.

In PfSenseOS the Routing Protocols and Routing Tables are managed natively by the FreeBSD kernel routing table, while dynamic routing protocols (OSPF, BGP, RIP) are handled by user-space daemons like FRRouting(FRR) or the native routed daemon. I believe Linux is somewhat similar to FreeBSD's but, has some differences on the compatibility level. I was so drawn to a FreeBSD derivative or, just a native FreeBSD OS install. I wanted to have the most secure OS performing these critical tasks and have always read that FreeBSD is one of the most secure OS's and that PfSenseOS is made specifically for a routing device. Eventually, I will get more practice with Linux kernel routing/firewall software and protocols.

_Unbound {

  • DNS resolver that will match a domain my devices type to an IP destination
  • Sits natively on my Routing device so my ISP doesn't perform DNS translation
  • Foundation that pfBlocker-NG sits on top of.

    • }

_pfBlocker-NG {

  • My network 'Bouncer', essentially. Works through Unbound and maintains a block-list
  • No ads, trackers, malware domains, and can can configure GeoIP to block entire countries
  • This is a network wide service and applies to all devices that route through this gateway

    • }

_Suricata {

  • The 'Guard Dog', essentially. Operates completely different than the other two
  • Sits on the wire and inspects the actual contents of my traffic in real time - by packet
  • Compares contents of packets to known attack signatures - malware, port scans, exploits.

}

My LAN Switch device is a Cisco 3750x Catalyst. This is a enterprise level Switch and has 48 ethernet ports and I don't have a Wireless Access Point (WAP) currently. All of my devices are hardwired when at home and then when I am out in public, I utilize the public Wifi and will make my way over to my Wire Guard VPN tunnel to hopefully avoid any sort of threat actor intercepting my packets.

I am aware that I can use the 3750x for Layer 3 IP routing etc but, due to the 3750x having a end of life sticker on it as of April 11, 2011 - I don't allow it to handle any sort of routing and firewall services. This device doesn't touch the WAN in any way. Its purpose is for me to practice with Cisco IoT devices. Plus, I was able to snag this for 40$ and all devices I use in my LAN will get their own VLAN.

VLAN segmentation is a great habit to adapt if you're serious about minimizing the blast radius of a device becoming compromised on your network. I give each device their own separate VLAN so any traffic they send or recieve will get broadcasted to the management VLAN interface called the Trunk. This will also reduce the broadcast domain noise and equal better performance. Every device on a flat network hears every other device's broadcast traffic (ARP requests, DHCP discovers, mDNS, etc.). I don't have that many devices on my homelab LAN so, this will be much more noticeable as you add more devices. Segmentation also allows for my firewall rules to be more meaningful instead of theoretical. I am able to allow inter-VLAN communications this way and is how I am able to SSH and SMB from device to another device.

I am enjoying this whole setup so far but, I eventually would like to slowly upgrade my devices and my next Switch will be a modern day Switch that doesn't have deprecated security software as well as learning the newer Cisco config commands and process in setting up VLAN's. I am taking more time to learn about basics in how our CPU's determine privileges and the 'protection rings' e.g. Ring 0 = Kernel mode aka supervisor mode, Ring 3 = User mode and where user space applications process runs. When they need to intereact with the hardware; depending on the hardware and OS, the OS Engineers will map their low level instructions like - read(), write(), fork(), etc. To different instruction codes that match the CPU's architecture - x86_64, ARM, ARM64. If a process crashes in user space, no big deal. If a process crashes in kernel space aka ring 0. That is what we call a 'kernel panic' aka bluescreen.

Apparently, these rings of protection go even lower than ring 0!!?? I know , I was just as shocked as you were when reading this. I will list the rings of protection below to hopefully paint a clear picture of this low level concept. As far as I can tell the -1, -2, and -3 aren't official area's that the manufacturers coined them but, it is what Cyber Security personnel have been calling them.

Lord of The Rings

Rings of protection {

  • Ring 0 : Kernel mode, has access to everything in the PC.
  • Ring 1 : Rings 1 and 2 are not used as often today and used to house drivers.
  • Ring 2 : Over the years OS manufacturers settled on 2 Ring layers for operation
  • Ring 3 : User space and is where the user is trusted to be.

}

Above you can see a diagram of what the modern rings of protection look like. It is quite interesting how it all works but, makes sense. We cannot be trusted to interact directly with the hardware and is enforced with the rings of protection and 'syscalls'.to interect with a kernel module - typically some sort of low level C code and even Assembly in some parts that require maximum efficiency.

I always find the abstraction process to be so interesting, and learning how drivers work in specific OS's can help you avoid headaches from time to time. In Linux the Kernel is a monolithic entity, and drivers run in kernel space - hence one of the reasons why Linux performance is looked at as the best. A fun way to look at how much time your program spends in kernel space and/or user space is by invoking the command 'time' and then append whatever program you want to pass through the time command.

Bash input : 'time python3 expense_tracker.py'

  • real 0m2.341s
  • user 0m2.210s
  • sys 0m0.089s

Now, I didn't actually run that command on that python program but, the output will be those bullet points to let you know how long each ring spends with computing the statements of your program. This is a fun tool to play around with and try to see if your program has a heavy amount of Syscalls it needs to make to be performing those low level C programs like read(), write(), ioctl().
